### 2026-08-21

1. **托盘唤起 v12：执行引擎切 pwsh 7**（`bin/lib/Functions.ahk`）
   - 修改：`TryTrayRestoreByNav` 的 `RunWait` 命令由 `powershell` 改为 `pwsh`（PS 7+，冷启动 ~260ms vs powershell 5.1 ~600ms）；`try/catch` 回退——无 pwsh 环境时自动改用 `powershell`（脚本本身保持 5.1/7 双兼容）
   - 原因：v11 回退后场景 A 仍 1.1-1.4s，实测分解确认耗时大头是 powershell.exe 5.1 冷启动（565-688ms，v10 基线首次 ~970ms 含系统冷缓存）+ UIAutomation 加载；pwsh 7 冷启动 254-265ms、加载 UIAutomation 后总约 360ms，且 tray_nav.ps1（5.1 兼容语法 + UIAutomationClient/Types 程序集）在 pwsh 7 下完整可用（实测 exit=0、窗口正常弹出）
   - 效果：真机实测（微信场景 A 全链）powershell 1277-1363ms → pwsh 525-571ms（ps1 侧 -58%）；AHK 调用链（TryTrayRestoreByNav + WinWait）797/875ms（原约 1.3s，-40%~-45%）；无 pwsh 的机器自动回退 powershell 行为不变；已部署 beta33（MD5/BOM 校验一致）并重启实例（4344+3316）

2. **托盘唤起极限提速 v11：隐藏窗口直连激活**（`bin/lib/Actions.ahk`）
   - 修改：
     - 新增 `RestoreHiddenWindow`（层 1）：`A_DetectHiddenWindows` 保存/恢复 + `WinGetList("ahk_exe …")` 枚举隐藏窗口（跳过 WS_EX_TOOLWINDOW、消息窗/IME/托盘宿主类）→ 仅对标题含 winTitle 的首个候选调用 `ShowAndActivate`（绝不误弹其他窗口）
     - 新增 `ShowAndActivate`：`ShowWindowAsync(SW_RESTORE=9)` 异步投递 + 轮询 `IsWindowVisible`（最多 300ms/20ms 间隔）——不用 `ShowWindow`/`WinActivate`/`SetForegroundWindow`：同步调用会等待目标窗口响应，微信 Qt/QQ Electron 窗口对激活消息响应慢时会阻塞数秒（探针实证）；SW_RESTORE 自带激活请求
     - `ActivateOrRun` 进程存在分支最前插入层 1：`RestoreHiddenWindow` 成功 → `WinWait(winTitle, , 0.5)` 验证后直接 return（不再 WinActivate）；层 2 兜底链不变（WinWait 0.3 → TryTrayRestoreByNav → 最终兜底 WinWait 2 → Tip），其中 TryTrayRestoreByNav 成功后 `WinWait 1.5 → 0.5`（ps1 v10 已内部轮询验证窗口可见，AHK 侧纯保险）
   - 原因：v10 后场景 A 仍 1.1-1.4s，耗时大头是 powershell.exe 5.1 冷启动约 970ms（引擎固有，UIA 托盘导航本身仅约 300ms）；决策门实测确认微信 4.0（Qt，类 `Qt51514QWindowIcon`）/QQ NT（Electron，类 `Chrome_WidgetWin_1`）关窗驻留 = 主窗口被隐藏（句柄保留）而非销毁 → AHK 进程内 ShowWindowAsync 即可直接恢复，完全绕开 PowerShell 冷启动与 UIA 链路
  - 效果：真机实测（微信/QQ 各 3 轮）场景 A 1102-1444ms → **125ms（-88%~-91%），与场景 B（125-141ms）完全持平**，24 倍差距彻底消除；每应用仅恢复一个可见主窗口（无多弹窗）；层 2 兜底回归 1375ms 完好（tray_nav.ps1 v10 未改）；行为不变（不发 Esc、无开始菜单、不重复启动）；已部署 beta33（MD5/BOM 校验一致）
   - **⚠️ 更正（同日用户实测后回退）**：层 1 方案被证伪——用户真机唤起微信/QQ 后窗口假死（可见但拒绝派发输入）。根因：用户真实点 X 关窗时 Qt/CEF 内部设置托盘模式标志，此后外部 `ShowWindowAsync(SW_RESTORE)` 强改可见性导致应用内部状态不一致（与历史 WinShow 卡死同根因）；v11 验证用 `ShowWindowAsync(SW_HIDE)` 模拟关窗，Qt 内部从未进入托盘模式，因此仅验证了"可见性"而未验证"可交互性"，属无效验证。**已回退**：`Actions.ahk` 恢复 v10 版（git checkout 0c18248，层 1 代码全部移除），重新部署 beta33（MD5 一致）并重启实例，唤起行为恢复 v10 实测状态（1.1-1.4s，功能正确）。

2. **后台程序托盘一键唤出（v9）**（`bin/lib/Actions.ahk` / `bin/lib/Functions.ahk` / `bin/lib/translation.ahk` / `bin/tray_nav.ps1`）
   - 修改：

     - `translation.ahk`：新增 `app_running_in_background` 中英文案
     - `bin/tray_nav.ps1`（新增，托盘唤起核心脚本，UTF-8 BOM，PS 托管 UIA）：v9 双路径——① 纯 UIA 展开：`Shell_TrayWnd` 子树 `FindAll(Descendants)` 找 Name="显示隐藏的图标" 的 Button（chevron）→ `InvokePattern.Invoke()` 展开溢出面板（重试 2 次防抖、面板已开则复用），**零键盘模拟**；② 面板匹配：`RootElement` 找类名 `TopLevelWindowForOverflowXamlIsland` → `FindAll(Descendants)` 枚举 Button（Name Trim）→ 两轮精确/包含匹配（排除输入法|指示器|网络|音频|音量|电源|时钟|通知|隐藏）→ `InvokePattern.Invoke()` 激活，激活后**绝不发 Esc**（微信视 Esc 为最小化）；③ 可见区兜底：面板未命中时枚举目标进程所有窗口+uid 0..9，`Shell_NotifyIconGetRect`（NOTIFYICONIDENTIFIER hwnd+uid，物理像素坐标，需 `SetProcessDPIAware`）即时定位 → `SetCursorPos` + `mouse_event` 单击 → `Test-WindowVisible`（MainWindowHandle != 0）验证 → 未弹出再双击（120ms 间隔）→ 1500ms 再验证；④ 日志：追加模式 + 每步时间戳（%TEMP%\mk_traynav.txt）
   - 原因：v7 用 `keybd_event` 模拟 Win+B 展开面板，四次独立调用非原子——Win down 瞬间弹开始菜单、B 被搜索框吞掉，用户实测失败（验证时通过属时序运气）；QQ（Electron，宿主 `Electron_NotifyIconHostWindow`）图标在托盘可见区（UIA 树不可见），单击无效、双击有效
   - 效果：微信/QQ 关窗驻留托盘后按快捷键直接唤出主窗口，无开始菜单闪现、无重复启动；`Actions.ahk`/`Functions.ahk` 已同步部署 beta33；日志全链路可查（`=== run` / `chevron invoked` / `panel appeared` / `MATCH` / `ACTIVATE` / `DONE (window visible)`）
